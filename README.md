# CO3029 — Urban Real Estate Valuation, Ho Chi Minh City

A reproducible course-project **starter implementation**, intended to be executed, inspected and independently revised by students before submission. The included LaTeX report is an **evidence-based draft**, NOT a completed experimental submission. No scores or charts are invented.

## Dataset and provenance
- Published dataset: **TiniX AI, Tinix Vietnam Real Estate Listings 2025–2026**, on Hugging Face mirror `vduydong/vietnam-real-estates-2`.
- 3,500,744 Vietnam listings; 1,357,526 listings labeled Hồ Chí Minh (source counts; not reproduced locally).
- Dataset: https://huggingface.co/datasets/vduydong/vietnam-real-estates-2 ; CC BY-NC 4.0; only *asking prices*, NOT finalized transaction prices.
- Script fetches 10-ish original Parquet files dynamically; filters HCMC and writes compressed Parquet. No large source data included in ZIP.

## Quickstart (Python 3.11 recommended)

```bash
python -m venv .venv
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
# macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
python scripts/download_data.py
python scripts/train.py --max-rows 80000
python scripts/export_report.py
streamlit run app/streamlit_app.py
```

For a full train set, pass `--max-rows 0` (very high memory and compute due to dense one-hot features). For a laptop, try `--max-rows 10000` initially. `python -m pytest -q` runs the smoke test.

If original dataset repository changes, `python scripts/download_data.py --repo OWNER/REPO` can target the same-schema Parquet dataset. Cache is local, and the output data is not committed.

## Experiment protocol
1. Filter Hồ Chí Minh; inspect missing fields, exact duplicates and price/area distribution.
2. Drop exact duplicates and invalid/missing targets, invalid areas, implausible price per m² (explicit fixed rule).
3. Reproducible sampling if required by compute capacity. Split training/development/test into **70% training, 10% calibration, 20% final test** (random seed 42).
4. Impute missing numerical features with training medians. Handle missing text with 'Không rõ'; limit category dimensionality through capped OneHotEncoder; standardize numerical inputs (inside cross-validation pipeline).
5. Compare Ridge, ElasticNet, RandomForest and Histogram Gradient Boosting; select hyperparameters using 3-fold randomized grid on log-price MAE. Choose model by CV only (not test score).
6. Report MAE/RMSE/R²/MAPE on unchanged original-VND target for test; save per-property predictions and permutation importance. Note that mean MAPE is very sensitive to small prices, so other metrics also matter.
7. Calibrate an approximately 90% **split conformal prediction interval** in log space with a separate held-out calibration sample. Report empirical test coverage. Do NOT call it a 95% confidence interval.
8. Streamlit demo accepts city property descriptors and displays estimate and interval.

### Important methodological limitations
- Random split can overestimate generalization for repeated or near-duplicate property listings. Exact duplicate removal does not guarantee removal of different ads describing one property. For a stronger study, add grouped/spatial/temporal validation and compare.
- Source fields are *listings*, not observed sale prices; the model estimates asking price, not fair market value.
- `price_per_m2` is used only for filtering bad training rows, never as a model feature (it would leak target).
- A prediction made for a future year or missing category is extrapolation and may be unreliable.
- Dense one-hot can exceed RAM on the full dataset; the default 80,000-row run is a controlled experiment, NOT proof of full-data training. Record hardware and resource budget.
- Interpretability uses model-agnostic permutation importance; optional SHAP can be added with measured runtime, not pretended.

## Optional sample-size experiment (without downloading data again)

Keep your existing `data/raw/hcm_listings.parquet` and **do not rerun** `scripts/download_data.py` or `scripts/train.py`. The experiment never changes `outputs/model.joblib`, `outputs/metrics.csv`, or the deployed Streamlit model.

```powershell
python scripts/learning_curve.py --sizes 3000 10000 30000 80000 --models HistGradientBoosting --test-size 20000
python scripts/export_report.py
```

Study files: `outputs/experiments/learning_curve.csv` (one row per fit), `learning_curve_summary.csv`, `learning_curve_mae.png`, `learning_curve_r2.png`, and `learning_curve_info.json`. For an optional stronger repeatability experiment, add `--repeats 3`; for a quick first run use `--sizes 3000 10000`.

**Design:** One 20,000-row random holdout from all eligible observations is kept fixed, independent of training sample size; training subsets are nested within a repeat; all imputers and encoders fit on training only. A different holdout seed from the original pipeline prevents direct apples-to-apples comparisons with the original leaderboard. This remains a random-listing split, vulnerable to near-duplicate properties, so it measures within-distribution generalization rather than unseen-property generalization.

**Important:** The study contains no hyperparameter tuning; fixed model settings are for observing the effect of sample size, not seeking a new winner. Inspect the graphs and write your own interpretation in the report.
